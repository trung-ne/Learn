# English Master — Global Project Rules ## Mission Build a complete self-study English learning system covering CEFR A1 through C2. The system should eventually support approximately 1,000+ hours of learning and include: - Grammar - Vocabulary - Vocabulary senses - Collocations - Lexical chunks - Pronunciation - Listening - Speaking - Reading - Writing - Communicative functions - Pragmatics - Reviews - Spaced repetition - Exercises - Unit tests - Level tests - Placement tests - AI listening practice prompts - AI speaking practice prompts - AI pronunciation prompts - AI writing tutor prompts Primary learner profile: Vietnamese learners of English. Vietnamese explanations may be used when pedagogically useful. --- # Core Principle Do NOT attempt to generate the entire A1-C2 course directly. The main product is a reproducible system that can: 1. collect permitted data 2. normalize data 3. validate provenance 4. classify linguistic content 5. construct curriculum 6. generate lessons 7. generate exercises 8. audit generated content 9. regenerate bad content 10. export approved learning materials Content generation must be reproducible and testable. --- # CEFR CEFR is the primary proficiency framework. Use authoritative CEFR resources as references. CEFR alignment must be represented explicitly in machine-readable data. Never trust a generator's self-declared CEFR level without independent validation. --- # Copyright Never crawl or copy educational content merely because it is available online. External sources must be registered before ingestion. Each source must have a status: - APPROVED - REFERENCE_ONLY - QUARANTINED - REJECTED Unknown licensing means QUARANTINED. REFERENCE_ONLY content may be studied for taxonomy or coverage but must not be copied into generated learning content. Never bypass: - authentication - paywalls - robots restrictions - rate limits intended as access controls - technical access restrictions Prefer: - official datasets - official APIs - official dumps - Creative Commons sources - public domain sources over scraping webpages. --- # Provenance Every externally sourced record must retain provenance. At minimum: - source_name - source_url - source_record_id - retrieved_at - license - attribution - content_hash - ingestion_version Generated material must retain: - generator - model when known - prompt_version - generated_at - curriculum_version - QA_status --- # Curriculum Curriculum must be dependency-based. Every concept should support: - id - name - CEFR level - prerequisites - related concepts - introduced_in - reviewed_in Lessons must not depend on concepts that have not been introduced. --- # Internal Levels Support: - A1.1 - A1.2 - A2.1 - A2.2 - B1.1 - B1.2 - B2.1 - B2.2 - C1.1 - C1.2 - C2.1 - C2.2 Lesson IDs should be deterministic. Example: A1-U01-L01 --- # Quality Generated content never automatically becomes approved content. Required QA categories include: - schema validation - CEFR validation - prerequisite validation - grammar validation - lexical validation - answer validation - ambiguity detection - duplicate detection - provenance validation - copyright validation - language quality review Whenever practical: Generator and Reviewer should be separate passes. --- # Development Process Work milestone by milestone. Do not silently begin the next milestone. For every milestone: 1. read specifications 2. implement only that milestone 3. add/update tests 4. run tests 5. inspect output 6. report failures 7. resolve failures 8. provide milestone summary 9. STOP A milestone is not complete while applicable tests fail. --- # Technology Direction Core pipeline: Python 3.12+ Preferred characteristics: - typed Python - structured schemas - pytest - reproducible command-line tools - deterministic identifiers - structured JSON/YAML data Do not introduce infrastructure unless there is a demonstrated need. Start simple. A future learner web application may use: - Next.js - TypeScript - PostgreSQL but web UI is not part of the initial milestones. --- # Repository Hygiene Never commit: - secrets - API keys - private credentials - enormous raw datasets - downloaded data with unclear redistribution rights Use environment variables when credentials become necessary. Maintain: .gitignore and documentation for all external dependencies. --- # Agent Behaviour Before modifying the repository: 1. inspect relevant specifications 2. inspect existing implementation 3. inspect tests Do not rewrite functioning architecture without explaining why. Avoid placeholders that pretend a feature has been implemented. TODO markers must describe specifically what remains incomplete. Never fabricate test results. Never claim a command passed unless it was actually executed. --- # Completion Rule When completing a task, report: - files created - files modified - commands executed - tests executed - pass/fail status - unresolved issues - next recommended milestone Then STOP.
